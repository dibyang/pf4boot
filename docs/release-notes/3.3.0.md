# pf4boot 3.3.0 发布说明

状态：功能冻结，2026-11-04 发布候选三项门槛通过；尚未正式发布。

## 范围

- 插件兼容范围与 capability 预检、离线仓库计划/替换、插件管理样例和基础应用模板。
- 显式 production profile 与真实签名校验；默认不启用严格模式。
- 任务排空、启动失败清理、销毁重试、调度回滚、依赖卸载、宿主 JSON/Spring 缓存和类加载器回收。
- Bug、安全报告及贡献文档。发布模块仍为 11 个框架模块，不包含 samples。

本版不再新增特性。方案及验收边界见 [发布收口](../design/release-3.3-closeout.md)。

## 升级步骤

1. 停止接入新工作，等待排空并确认旧宿主正常关闭；对旧宿主、插件、配置、业务数据库及治理记录做一致的离线备份。
2. 将宿主使用的全部 pf4boot 模块统一升级到 `3.3.0`，清理 lib 中旧框架 JAR，保留已验证的 Spring Boot/PF4J 依赖组合。继续使用 Java 8；不要顺便升级宿主技术栈。
3. 先保留原有默认配置和旧插件二进制，验证业务、事务、停止/启动、卸载和异常恢复，再逐项启用可选治理能力。
4. production profile 为显式选择。原始旧包缺少 checksum、兼容/信任清单和可信签名时会被拒绝；需经维护者确认兼容范围并生成有效清单和签名后再启用，不应关闭必要校验来绕过失败。样例公钥仅用于验收，不能作为生产信任根。

## 必须注意的行为修正

- 排空超时、销毁或类加载器关闭失败不再报告成功；调用方必须处理异常，不得继续替换/重启并丢弃欠清理实例。
- 排空/销毁失败可在修复原因后通过既有 stop/start/unload 路径重试；类加载器部分关闭失败不得直接 start，应先成功卸载并重新加载。manager 已开始关闭后不可再次激活，应创建新 manager。
- 已成功执行的销毁回调不会重跑；同一对象重复销毁被去重。失败回调须支持重试，不能依赖此前的漏销毁或重复调用。
- 清理回调内部同步递归启停会被拒绝；应在本次操作完成后发起下一次操作。释放钩子追加钩子时，尚有欠清理资源即显式失败，不无限执行自追加回调。
- UNLOADED 通知在整批资源释放后发送，监听器不得假定旧 loader 或同批依赖仍可用；监听器异常不会回滚已经完成的资源释放。
- 公共 API、默认配置、插件 ZIP 格式和本轮资源修复涉及的存储格式保持兼容；这不等同于所有自定义扩展或任意历史插件都已验证。未登记的自建线程/外部资源仍由插件负责释放。

## 回滚

先停止流量并完成新版本排空和关闭。不能通过替换文件绕过清理失败。恢复整套旧宿主、旧插件、配置及升级前一致备份；不要混用两版框架 JAR。新版本产生的数据若需保留，应先做业务级迁移评估，本版不承诺任意新治理记录可被旧框架读取。

```powershell
.\gradlew.bat '-Dorg.gradle.java.home=C:\Program Files\Java\jdk-1.8' build publishToMavenLocal :samples:cross-plugin-jpa:app-run:compileSmokeJava :samples:saga-outbox:app-run:runtimeSmoke

```

复验须使用新导出目录。独立消费工程的 build.gradle/settings.gradle 使用验收目录内 `consumer.gradle`/`consumer.settings.gradle`，只复制 demo-host 的 src/main，不包含仓库 settings 或 project 依赖。导出读取已完成的框架 JUnit XML、`build/release-3.3-consumer/build/runtime/lib` 及 `build/release-3.3-baseline/pf4boot-cross-plugin-jpa-sample`。保留原始旧发行 ZIP，禁止用新版插件替代旧包。

在首次运行前仅封存一次：`python verify.py --seal`。Windows 显式传 Java 8 路径，Linux 在隔离目录用已有低权限用户依次执行：

```sh
python3 verify.py --java /usr/bin/java --port 17832
python3 release_upgrade.py --java /usr/bin/java --port 17832
```

执行后再次核对所有输入哈希；不能重新 seal 掩盖变化。已有工作/数据目录必须保留，不在同一导出目录重复执行。
